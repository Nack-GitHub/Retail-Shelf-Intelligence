# UAT — สิ่งที่ต้องรู้ก่อนเริ่มทดสอบ

> รอบนี้ทดสอบ **ประสบการณ์ใช้งานและความถูกต้องของ flow**
> **ไม่ได้ทดสอบความแม่นของโมเดลตรวจจับ** — อ่าน §2 ก่อนแจ้งผลตรวจจับเป็น defect

---

## 1. การ build และ deploy

```bash
# frontend — อย่าตั้ง NEXT_PUBLIC_DEMO_MODE
cd frontend && npm run build && npm run start

# backend
cd backend && ENVIRONMENT=uat JWT_SECRET=$(openssl rand -hex 32) ...
docker compose --profile app --profile real-ml up -d
```

**`NEXT_PUBLIC_DEMO_MODE` ต้องไม่ถูกตั้ง** ถ้าตั้งเป็น `1` เครื่องมือสาธิตจะกลับมา —
ปุ่มบังคับสถานะหน้าจอ แผงบัญชีที่โชว์รหัสผ่าน และหน้าเลือกแพลตฟอร์มที่ `/`

ตรวจว่า build ถูกต้อง:

```bash
cd frontend
# 1) รหัสผ่านและอีเมลบัญชีสาธิตต้องหายไปจากบันเดิล
grep -r "demo1234"      .next/static   # ต้องไม่พบ
grep -r "shelfeye.demo" .next/static   # ต้องไม่พบ
grep -r "โหมดสาธิต"      .next/static   # ต้องไม่พบ

# 2) ทุกเงื่อนไขต้องถูก fold เป็นค่าคงที่ตอน build
grep -r "NEXT_PUBLIC_DEMO_MODE" .next/static   # ต้องไม่พบ
```

> **หมายเหตุ:** สตริง `"สาธิตสถานะหน้าจอ"` จะยังค้างอยู่ในบันเดิล — Turbopack เก็บโมดูล
> ที่ถูก import ไว้แม้เงื่อนไขที่เรียกใช้จะถูกตัดทิ้งไปแล้ว **ไม่มีเส้นทางไหนใน UI ที่
> render มันได้** เพราะเงื่อนไขทุกจุด fold เป็น `false` ตั้งแต่ตอน build
> ข้อพิสูจน์คือ `npm run test:e2e` (ชุด `demo-off.spec.ts`) ที่ยืนยันว่าไม่มีปุ่มพวกนี้
> อยู่ใน DOM จริง ๆ

**บัญชีผู้ใช้ต้องสร้างเอง** `make seed` จะปฏิเสธถ้า `ENVIRONMENT` ไม่ใช่ local/ci/demo
เพราะบัญชี `@shelfeye.demo` ทั้งสี่ใช้รหัสผ่านเดียวกันที่เขียนอยู่ในซอร์ส และหนึ่งในนั้น
เป็น ADMIN เช่นเดียวกับ `JWT_SECRET` — API จะไม่บูตถ้ายังใช้ค่าที่เคย commit ไว้

## 2. ⚠️ ข้อจำกัดของโมเดล — อ่านก่อนแจ้ง defect

โมเดลที่ใช้คือ `shelf-product-yolo26l-960` ซึ่ง **ไม่ผ่านเกณฑ์ที่โครงการตั้งไว้เอง**:

| เกณฑ์ | ต้องได้ | ได้จริง | |
| :-- | --: | --: | :-- |
| Recall (คลาสช่องว่าง) | ≥ 0.90 | **0.74** | ❌ |
| Precision (คลาสช่องว่าง) | ≥ 0.85 | **0.75** | ❌ |
| mAP@0.5 ทุกคลาส | ≥ 0.85 | 0.91 | ✅ |

แปลเป็นสิ่งที่จะเห็นบนจอ:

- **ช่องว่างจริงราว 1 ใน 4 จุด โมเดลจะตรวจไม่เจอ** — ชั้นวางที่มีของขาดแต่ระบบบอกว่าครบ
  ไม่ใช่บั๊กของแอป
- **สิ่งที่ระบบแจ้งว่าเป็นช่องว่าง ราว 1 ใน 4 จุด จะไม่ใช่** — กดปุ่ม "ไม่ใช่" แล้วเลือกเหตุผล
  คือการใช้งานที่ถูกต้อง ไม่ใช่การรายงานข้อผิดพลาด

หน้า **สุขภาพของโมเดล** (`/w/model-health`) แสดงแบนเนอร์แดงบอกเรื่องนี้อยู่แล้ว
**แบนเนอร์นั้นถูกต้อง อย่าแจ้งเป็นบั๊ก**

**สิ่งที่ควรแจ้ง:** กล่องครอบวาดผิดตำแหน่ง · ตัวเลข OSA ไม่ตรงกับจำนวนช่องว่างที่เห็น ·
ผลหายหลังกดยืนยัน · แอปค้าง/หน้าขาว · ข้อความไทยผิด · ปุ่มกดไม่ได้
**สิ่งที่ไม่ต้องแจ้ง:** โมเดลมองไม่เห็นช่องว่างบางจุด หรือแจ้งเกินบางจุด

## 3. สิ่งที่ยังไม่เปิดใช้งานในรุ่นนี้

| สิ่งที่เห็น | สถานะ |
| :-- | :-- |
| **การเบลอใบหน้าอัตโนมัติ** | **ยังไม่มี** — หน้ากล้องเขียนบอกไว้ ผู้ถ่ายต้องเลี่ยงไม่ให้ลูกค้าหรือพนักงานร้านติดอยู่ในเฟรมเอง |
| ปุ่ม "ส่งออกรายงาน" (`/w`) | disabled พร้อมป้าย "เร็ว ๆ นี้" |
| การจัดลำดับ + "ทำเครื่องหมายว่าตรวจแล้ว" (`/w/routes`) | ไม่ถูกบันทึก หายเมื่อรีเฟรช — มีข้อความบอกใต้ปุ่ม |
| คิวตรวจภาพ (`/w/relabel`) | เลือกภาพได้ แต่ยังไม่ส่งเข้ารอบเทรน |
| ปุ่ม "โต้แย้งผลนี้" | บันทึกในหน้าจอเท่านั้น ยังไม่ส่งต่อทีมข้อมูล |

## 4. สิ่งที่ดูเหมือนข้อมูลขาด แต่เป็นข้อกำหนด

**"ผู้ถ่าย: พนักงานภาคสนาม"** ในหน้าต่างหลักฐาน — ขึ้นแบบนี้เสมอทุกภาพ ไม่ใช่ข้อมูลหาย

ระบบ**ห้ามผูกตัวเลขใด ๆ กับพนักงานรายบุคคล** ([ui.md](ui.md) §1.5 ข้อ 4) เพราะถ้าผู้จัดการ
เห็นว่าใครถ่ายภาพไหน ก็จะนับเองได้ว่า "ภาพของคนนี้โดนตีกลับบ่อยกว่า" ซึ่งกลายเป็นคะแนน
รายคนทางอ้อม ข้อห้ามนี้บังคับที่ backend ด้วย test 7 ตัวใน `test_prohibitions.py`
API ไม่เคยส่งชื่อหรือ id ของพนักงานออกมาเลย

ด้วยเหตุผลเดียวกัน: ไม่มี leaderboard ไม่มีคะแนนรายคน และไม่มีปุ่มใดที่ให้ระบบติดต่อร้านค้า
โดยอัตโนมัติ — **ทั้งหมดนี้ตั้งใจ**

## 5. วิธีสร้างสถานะทดสอบ (แทนปุ่มบังคับสถานะที่ถอดออกแล้ว)

รุ่นสาธิตเคยมีปุ่มกดสลับหน้าจอได้ทันที รุ่นนี้ไม่มี — ต้องสร้างสถานการณ์จริง:

| อยากเห็น | ทำอย่างไร |
| :-- | :-- |
| GPS ไม่ตรงกับที่ตั้งร้าน | เช็คอินจากนอกรัศมี 150 ม. จากพิกัดร้าน (แก้ `GPS_MATCH_RADIUS_METERS` ได้) |
| วิเคราะห์ภาพไม่สำเร็จ | ถ่ายภาพที่ไม่ใช่ชั้นวาง เช่น พื้นหรือเพดาน |
| จุดที่ระบบไม่มั่นใจ | ถ่ายชั้นวางย้อนแสง หรือมีของบังบางส่วน |
| ไม่มีงานให้แก้ (OSA 100%) | ถ่ายชั้นวางที่เต็ม แล้วกด "ไม่ใช่" กับทุกจุดที่ระบบแจ้ง |
| คิวรอส่งข้อมูล / ออฟไลน์ | เปิด airplane mode ระหว่างกด "ใช้ภาพนี้" แล้วเปิดเน็ตกลับมา |
| ไม่มีร้านในเส้นทาง | ใช้บัญชีที่ `areaId` ไม่มีร้านอยู่ |
